# 虚拟展示用户

管理入口：**管理后台 → 虚拟展示用户**。这些人物只用于影片卡片的社区风格展示，不是真实上传者，也不是可登录账号；不会复制真实账号的用户名、昵称、头像或权限。

- 每次可批量生成 1–100 个独立虚拟人物，可编辑展示名、头像、启用状态。
- 生成请求带持久幂等标识：请求超时后重试同一批不会重复生成；同一标识不能换成不同数量。
- 头像可留空，或填写 HTTPS 地址、站内绝对路径。服务器不抓取外部头像。
- 空人物池不会自动从真实用户补位，也不会伪造账号。
- 影片首次返回展示时，从启用人物中自动匹配，并将匹配关系独立持久保存。本地影片、远程源影片都适用，无须导入影片或产生上传操作。
- 增加人物不重排已有匹配。停用人物后，其匹配影片隐藏这项展示；重新启用即恢复原关系。编辑名字或头像会同步反映到已匹配影片。
- 同一源和影片的原始 ID / 源前缀 ID 使用相同匹配；不同源分别匹配。卡片明确标识“虚拟展示”，不表示该人物实际上传或拥有影片。

## 数据与升级

新增 `VirtualUploader`、`VideoAttribution`、`VirtualUploaderBatch` 三张独立表，不关联 `User`，不迁移或覆盖真实账号资料、片源、影片、会员、钱包等已有数据。不提供删除人物操作，以保留稳定关联；需要撤下时使用停用。

部署前备份数据库，沿用项目现有 `db:generate` 和非破坏性的数据库准备/同步流程。新增表需要完成数据库同步后才可使用管理页。展示关联失败不会影响影片正常返回，也不会回退使用真实账号。
