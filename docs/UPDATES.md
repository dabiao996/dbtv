# 正式版检查与增量更新

## 当前状态

后台「系统 → 系统更新」只接受 `dabiao996/dbtv` 的签名正式版。已发布的 `v1.0.1` 不包含本分支的一次性增量更新代码。当前以 Vite 运行的 `127.0.0.1:5173` 站点不能凭网页把尚未安装的更新器加载进来；首次引入这段程序代码需要另行核对本地修改后，由用户明确决定。此分支未更新当前站点，也未发布新版。

本分支的 macOS 开发站只有在使用项目 `npm dev` 的监看模式、且运行环境显式设置 `DBTV_LOCAL_DIFF_UPDATES=1` 时，才允许已登录的管理员在后台发起**一次性**本地更新任务。它不安装 LaunchAgent、不运行常驻更新代理、不用 root、不开放额外监听端口。网页仍须通过服务器端管理员鉴权、同源检查、重新验证当前密码和确认操作；请求只含固定动作与正式版本号。服务器启动独立子进程处理任务，避免源文件更新导致网页进程重启时中断任务。

## 更新边界

1. 后台列出固定 GitHub 仓库近 20 个正式 Release，选择版本时单独验签。一次性进程再次验证 Ed25519 签名、固定发行来源、源码包 SHA256、发行版本和公钥。任意下载地址、命令、路径和未签名清单都不是网页参数。数据库兼容时可选择较旧正式版，切换的只是程序。
2. 当前程序的数据库兼容标识必须与所选签名清单完全一致，并与本地实际结构标识一致。标识变化会在写文件前阻止更新；数据库迁移需要用户单独决定。新发行的标识覆盖 Prisma schema 及显式数据库迁移/初始化代码，普通前后端改动不会误判为结构变化；旧 `v1.0.1` 使用更宽的标识计算方式，因此默认不视为可自动切换的兼容版本。
3. 源码包只允许已列明的程序目录和文件，拒绝路径穿越、符号链接及特殊文件。按文件内容哈希计算差异；已有 Git 文件须与 `HEAD` 一致，或与上次成功更新的程序清单一致。本地改动和未跟踪的同名文件会阻止覆盖。首次无程序清单时，不自动删除旧文件；后续只清理清单中记录且未被本地修改、又已从发行包移除的程序文件。
4. `data/`、`live-tv.json`、SQLite 数据库及 WAL、账号、`.env`、日志、备份和 `node_modules` 均不从发行包覆盖。已有备份保持原样；更新不自动新建备份，也不强制用户备份。成功后只保存不含私有数据的程序哈希清单。
5. 依赖图不变则不运行依赖安装，即使版本号更新使锁文件元数据变化。依赖图变化时用 npm 基于签名锁文件进行增量同步，不手工复制 `node_modules`；拒绝未知依赖安装脚本。已审核的 Prisma／esbuild 变化才执行对应必要步骤。涉及前后端程序时运行构建，并核对运行中的后端版本。

更新会逐个原子替换程序文件，**不能在无备份条件下保证整个目录原子切换或自动数据回滚**。构建、依赖同步或进程重载中断后，任务标记为阻塞并保留现场，不自动重试、删除数据或宣称更新成功。开发站的 `tsx watch`／Vite 通常会因源码变化重载；若后端没有重新响应目标版本，后台明确要求人工检查并重启原有开发服务，不擅自杀进程或重新初始化部署。生产服务需要经审查的服务管理方式，本一次性开发站流程不把它伪装为已支持。

以前的 Linux/Termux 托管更新代码仍保留程序版本切换及手动 `backup` 命令，但本分支移除了切换时的自动备份及备份成功门槛。兼容时可以尝试仅恢复旧程序；数据库和直播 JSON 不回退。旧主机已经复制的管理代码不会随源码改变，不能假定它已采用本分支的新行为。

## 发布与签名

正式发行时，`package.json`、`package-lock.json`、`release.json` 版本一致，主分支保留 `development`。已有 `.github/workflows/release.yml` 在标签触发后运行检查、生成源码包及镜像摘要，用离线配置的 `RELEASE_SIGNING_KEY` 签名清单，再发布正式 Release。私钥不得提交到源码、发送到聊天、写入站点或更新队列。发行包只含公开源码及 `live-tv.example.json`，不含旧站私有频道目录。

本分支没有创建标签、推送 GitHub、安装代理或执行当前站点升级。发布新版本及把一次性入口引入当前开发站均需分别评估；已发布的 `v1.0.1` 不能反向获得未发布的网页更新能力。

## 验证范围

隔离测试覆盖签名和来源、管理员鉴权及同源要求、数据库兼容阻断、锁文件未变时跳过安装、锁文件变化时调用 npm、未知安装脚本阻断、本地修改保护、程序文件差异、持久数据不变及失败后阻塞。尚未在用户当前站点执行真实升级，也未验证真实发行包更新时开发进程一定会自行重启。
