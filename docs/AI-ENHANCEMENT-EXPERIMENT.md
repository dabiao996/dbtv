# 浏览器本地 AI 画质增强实验

这是手动、默认原画的播放器实验功能。可选择「动画 · Anime4K CNN」或「真人 · WebSR 实验」，再选轻量 S、标准 M、高负载 L。选择后才请求对应的本地静态模型、加载 WebSR 并申请观看设备的 WebGPU；视频帧不发送给模型服务。播放器原有的 `<video>` 始终负责解码、音频、进度、字幕与原生控件，模型结果作为同尺寸画布叠在上面。按住「原画 A/B」可看原视频。

动画模式采用 Anime4K 原始 `-an` CNN 权重。真人模式采用 WebSR 维护者重训的 `-rl` 权重；上游明确说真人权重的主观效果不如动画权重。L 只代表网络更大、负载更高，不代表已验证的真人画质提升。界面报告解码输入、模型输出和实际播放窗口尺寸，方便判断是否仅把像素放大；这些尺寸也不是画质评分。

## 本机启动和测试

需要 Node.js 20.19+ 或 22 LTS。独立开发副本中运行：

```bash
npm ci --ignore-scripts
npm run db:generate
npm run dev:client -- --host 127.0.0.1
```

浏览器打开 `http://127.0.0.1:5173/ai-lab.html`。该页面不需要后端，可选择本机已获授权的视频，也可生成三秒无版权合成片段用于功能测试。所选文件通过 object URL 留在浏览器本地；离开页面或换文件时 URL 会撤销。合成片段不能用于判断真人画质。完整网站的播放器入口仍是 `/player/...`，需要按 README 配置本地后端和自己的授权片源。

测试应暂停在同一帧、保持播放器尺寸不变，按住 A/B 对比线条、发丝、皮肤与伪影，再检查运动时闪烁和掉帧。记录浏览器、设备、视频原始尺寸、码率或来源、模型档位、主观细节与伪影、平均帧耗时及启用后的浏览器掉帧数。界面帧耗时包含 GPU 队列完成等待，不含第一次着色器编译；它不是画质评分。真人内容是否清晰改善，必须用有许可的代表性真人片段实测，不能由合成片段推断。手机、电脑和电视浏览器都以同样方式检测支持情况，不保证均可用。

## 边界与回退

- 需要安全上下文、WebGPU、`requestVideoFrameCallback` 和可读取的视频帧。跨域无 CORS、DRM 或其他保护内容不尝试绕过；检测失败立即播放原画。
- 暂停时不继续逐帧推理；定位时先显示原画，新的画面就绪后再渲染。换集和切源会卸载旧会话，关闭开关会取消帧回调并销毁 GPU 设备。
- WebGPU 丢失、分辨率改变、模型与网络不匹配、画布尺寸或对齐异常、渲染出错、画中画、投屏、原生视频全屏及播放结束会停用增强并显示原因。播放器容器全屏按钮会一起容纳画布与控件。原生字幕正在显示时回退原画，以保留字幕而不覆盖字幕。
- 原生视频控件仍可操作。控件出现时增强画布会避开底部控件区域；其余时间覆盖完整画面。慢设备显示性能提醒，用户可换轻量档或关闭。

## 来源及模型性质

使用固定版本 `@websr/websr@0.0.16` 的 TypeScript 源码入口；官方 npm 发布包另含 Webpack 开发式 UMD 包，Vite 构建改用包内源码避免将其 `eval` 输出带入本站。npm 包没有安装生命周期脚本。项目仍处于上游明确标注的实验阶段。

S/M/L 是 WebGPU 逐帧 CNN。S 产生统一明暗残差，M/L 产生 RGB 残差，由 pixelshuffle 与线性插值底图合成 2 倍画面；不是时序恢复、解码修复或简单锐化。播放器保持既有观看尺寸，不硬编码 720p 或 1080p。六组模型均来自固定版本 WebSR 0.0.16 的 npm 包：

WebSR 及原 Anime4K 均为 MIT，许可正文随模型保存在 `client/public/models/websr/`。WebSR 的真人权重由其维护者在 Xiph 素材上重新训练；不要求本项目重新训练。未采用另一个 `anime4k-webgpu` npm 后端：它的高层视频包装器自行管理视频渲染循环，当前播放器需要可立即停止、定位和切集的显式生命周期；本次采用现有已审计 WebSR 网络中的 Anime4K 原始权重，避免为类似算法再引入并行渲染器。
